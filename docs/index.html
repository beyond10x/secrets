Secrets API

Tenant-scoped encrypted secret custody for people and workloads. The canonical machine-readable contract is OpenAPI 3.1.

Safety model

  • Secret values appear only in bounded JSON request or response bodies.
  • User endpoints expose metadata, revocation, and deletion. They never reveal connector-created values.
  • Workload credentials are projected Kubernetes service-account tokens with an exact audience.
  • Every reference includes a tenant, namespace, and key; authority is checked before storage access.

Endpoints

  • User GET /v1/user/secrets, POST /v1/user/secrets:detail, POST /v1/user/secrets:revoke, DELETE /v1/user/secrets
  • Workload put/get/exists/delete at /v1/workload/secrets*
  • Batch prepare, commit, or abort under /v1/workload/tenants/{tenant}/transactions
  • Operations /health/live, /health/ready, and /metrics
